# Airport Hub DB

> Сухоручкин Артём Андреевич Б05-413

Проект - база данных аэропорта, которая связывает рейсы, 
пассажиров, бронирования, самолёты, полосы и временные слоты. Идея - автоматизировать поддержку логики и предотвращения ситуаций, 
где ошибка в данных сразу приводит к ошибке в работе аэропорта (а то и к убыткам или даже катастрофа): одно место не должно продаваться дважды, 
билет нельзя оформлять после начала посадки, а две операции на одной полосе не могут пересекаться по времени. 
Эти правила заложены в саму базу данных, чтобы система сразу отсекала некорректные действия и 
сохраняла согласованность между расписанием, билетами и разными операциями, запросами.

## Поддерживаемые инварианты

БД поддерживает четыре основных инварианта на уровне схемы:
- бронирование мест с гарантией уникальности;
- распределение слотов на ВПП без пересечений;
- назначение экипажа с проверкой норм отдыха и устранения накладок с другими рейсами;
- контроль цикла жизни рейса как конечного автомата.

## Структура репозитория

- `./schemas/` — концептуальная, логическая, физическая схемы
- `./data/` — CSV-данные для заполнения (≥ 20 строк на таблицу)
- `./base_part/` — DDL, заполнение, 10 SELECT-запросов
- `./advanced_part/` — индексы, представления, функции, триггеры
- `./tests/` — pytest-тесты на функции и триггеры

## Создание БД

```bash
psql -d postgres -f base_part/create.sql
psql -d postgres -f base_part/insert_data.sql
psql -d postgres -f advanced_part/indexes.sql
psql -d postgres -f advanced_part/views.sql
psql -d postgres -f advanced_part/functions.sql
psql -d postgres -f advanced_part/triggers.sql
```

## Запуск тестов

```bash
cd tests
pytest -v
```

## Реализованные пункты

**Обязательные**: схемы (концептуальная/логическая/физическая), создание и заполнение БД, 10 SELECT-запросов.

**Дополнительные**: 3 индекса (включая partial и unique), 2 представления, 4 функции, 2 триггера, покрытие тестами позитивных, негативных, граничных и конкурентных сценариев.
